# R-#11: R-#11 Implement Blockchain Case Certification

After a case passes the final validation by the `Publishing Validator`, its integrity must be immutably recorded on the Celo blockchain. This involves calculating a hash of the case's core data and calling a smart contract function to store that hash permanently.

**Tasks:**
- [ ] Design and deploy a `CaseCertification.sol` contract on Celo.
    - It should have a `certifyCase(uint256 caseId, bytes32 caseHash)` function, callable only by the `Publishing Validator` (or a designated admin wallet).
    - It should emit a `CaseCertified(uint256 caseId, bytes32 caseHash, uint256 timestamp)` event.
    - Store a mapping from `caseId` to the certification details (hash, timestamp, certifier).
- [ ] In the Publishing Validator dashboard, after clicking "Approve", the system should:
    - Fetch the case data from the Rails backend.
    - Generate a deterministic hash (e.g., SHA-256 of a canonical JSON representation of the case). **Important:** Exclude any fields that might change over time (e.g., "last_updated"). Only hash the immutable core facts.
    - Call the `certifyCase` function on the `CaseCertification` contract.
    - Wait for the transaction receipt and store the transaction hash in the database (linked to the case).
- [ ] Update the case view page to display a "Certified on Celo" badge with a link to the transaction on CeloScan.

**Acceptance Criteria:**
- [ ] The `CaseCertification` contract is deployed and verified on Celo.
- [ ] A Publishing Validator can certify a case, generating a blockchain transaction.
- [ ] The case hash is stored on-chain and is immutable.
- [ ] The case view page shows a link to the certification transaction.
- [ ] The same case, if certified again (should not happen), produces the same hash (idempotent).
