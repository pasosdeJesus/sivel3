# R-#63: Update to Next.js 16

Evaluate and migrate sivel3 to Next.js 16, which changes the default bundler
from Webpack to Turbopack. Turbopack requires native bindings unavailable on
adJ/OpenBSD — resolved via `--webpack` flag ([next.js#89305](https://github.com/vercel/next.js/issues/89305)).

Also requires `@pasosdejesus/m` v0.16.0 (dist fixes for Next.js 16 types).

## 1. Contexto

### 1.1 El problema

Next.js 16 usa **Turbopack como bundler por defecto** en desarrollo. Turbopack
requiere bindings nativos (`next-swc`) que no existen para `openbsd/x64`.
Next.js 15.5.x funciona porque ofrece Webpack como alternativa; en v16,
Turbopack es forzado a menos que se use `--webpack`.

```
$ next dev
Error: turbo.createProject is not supported by the wasm bindings.
```

### 1.2 La solución oficial

[next.js#89633](https://github.com/vercel/next.js/pull/89633) (merged canary):
mensaje de error claro + flag `--webpack` para forzar Webpack en desarrollo.

```bash
next dev --webpack     # ✅ desarrollo con Webpack
next build             # ✅ producción usa Webpack por defecto
```

### 1.3 m v0.16.0

`@pasosdejesus/m` v0.16.0 incluye `dist/` corregido con tipos compatibles
con Next.js 16. Requerido para que `make type` pase sin errores.

## 7. Puntos importantes para migrar a Next.js 16 en adJ/OpenBSD

### 7.1 Turbopack no soportado → `--webpack` obligatorio

Next.js 16 usa Turbopack por defecto, que requiere bindings nativos
(`next-swc`) inexistentes para `openbsd/x64`. Forzar Webpack en **dev y build**:

```json
"dev": "next dev --webpack",
"build": "next build --webpack"
```

Referencia: [next.js#89305](https://github.com/vercel/next.js/issues/89305).

### 7.2 Límite de memoria `ulimit -d`

Next.js 16 compila con Webpack y el V8 crashea (GC fatal, `Trace/BPT trap`)
si el límite de datos (`ulimit -d`) es bajo (1.5G por defecto en adJ).
Subir a **7G** antes de `next build`:

```sh
sh -c 'ulimit -d 7340032 && pnpm build'
```

Sin esto, el build falla con un crash de V8, no un error de compilación.

### 7.3 `eslint` removido de `NextConfig`

La opción `eslint` del `next.config.ts` ya no existe en v16. Remover:

```diff
- eslint: { ignoreDuringBuilds: true },
```

### 7.4 Config ESM — `__dirname` no disponible

Next.js 16 trata `next.config.ts` como módulo ES. `__dirname` ya no está
definido. Usar `import.meta.url`:

```typescript
import { fileURLToPath } from 'url';
import path from 'path';
const __dirname = path.dirname(fileURLToPath(import.meta.url));
```

### 7.5 Dependencias opcionales `@x402/*`

`@coinbase/cdp-sdk` (vía wagmi → rainbowkit) importa `@x402/*` que no se
instalan en adJ/OpenBSD. Aliasear a `false` en `webpack.resolve.alias`:

```typescript
webpack: (config) => {
  config.resolve.alias = {
    ...config.resolve.alias,
    '@x402/core': false,
    '@x402/core/client': false,
    '@x402/evm': false,
    '@x402/evm/exact/client': false,
    '@x402/evm/upto/client': false,
    '@x402/svm/exact/client': false,
  }
  return config
}
```
