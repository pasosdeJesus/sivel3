## 1. Objective

Make sivel3 easy to adopt and trustworthy by flipping the wallet priorities:

1. **In-app wallet (self-custodied) as the primary** way to connect/sign, so a
   new user does not need any browser extension.
2. **External wallet as an option** (for reliability / advanced users), via a
   **thin EIP-6963 connector** — no vendor UI kit.
3. **Retire RainbowKit and WalletConnect**, and **de-prioritize/remove MiniPay**
   (sivel3 was not approved in its store, so it is no longer a target).

This also makes the browser/signature e2e suite (REQ/66 Block B) trivial to
mock: `@pasosdejesus/m/e2e`'s `injectEIP6963` + real signer target exactly the
**EIP-6963 + in-app** stack, whereas RainbowKit + WalletConnect requires driving
a modal and a QR flow in Puppeteer.

## 2. Background — measured state (2026-10-08)

### 2.1 Current sivel3 stack (RainbowKit + WalletConnect + MiniPay)

- `providers/AppProvider.tsx`: `connectorsForWallets([okxWallet,
  walletConnectWallet, metaMaskWallet, injectedWallet])` with
  `projectId: NEXT_PUBLIC_WC_PROJECT_ID`, wrapped in `RainbowKitProvider`; plus a
  **MiniPay legacy-tx patch** that monkey-patches `window.ethereum.request`
  (removes EIP-1559 fields).
- `contexts/WalletContext.tsx`: uses wagmi `useAccount`/`useConnect` and
  superimposes **MiniPay** state (`useMiniPay`), exposing `isMiniPay`,
  `phoneNumber`, `connectMiniPay`.
- `hooks/useMiniPay.ts` (31 refs) and `hooks/useAutoConnect.ts`: MiniPay
  detection (`ethereum.isMiniPay`, `minipay_getPhoneNumber`) and auto-connect.
- `lib/donate.ts`: MiniPay uses `ethereum.send` (MiniPay rejects
  `ethereum.request` for sends); MetaMask path differs.
- `lib/buyPreAlert.ts`: MiniPay uses `ethereum.send` + calldata-stuffing
  (`extractMiniPayHash`); comment "Follows the same MiniPay-compatible pattern".
- `components/ConnectWalletButton.tsx`: RainbowKit `ConnectButton.Custom`.
- Deps: `@rainbow-me/rainbowkit`, `@rainbow-me/rainbowkit-siwe-next-auth`,
  `wagmi`, `viem`, `@tanstack/react-query` (keep wagmi/viem/react-query).

### 2.2 learn.tg already made this move (reuse it)

learn.tg left RainbowKit and WalletConnect and now uses:

- `apps/nextjs/lib/external-provider.ts`: resolves the external provider via
  **EIP-6963** announcements (`eip6963:announceProvider` / `:requestProvider`),
  keeps `window.ethereum` as fallback and retries on late injection (Rabby,
  MetaMask, OneKey mobile announce late); the choice is sticky per page session.
- `apps/nextjs/lib/hooks/useWalletProvider.ts`: **effective EIP-1193 provider =
  in-app (when unlocked) ?? external**.
- `@learn-tg/pdj-wallet` (framework-agnostic in-app wallet; viem-only) +
  `@learn-tg/pdj-wallet-next` (`useInAppWallet`, `InAppWalletSetup`,
  `InAppWalletUnlock`). Its README explicitly lists **sivel3** as a target
  consumer ("learn.tg today; sivel3 and stable-sl later").
- UI split into `WalletSelector`, `WalletDialog`, `WalletPanel`,
  `WalletEventListener`, `ConnectWalletButton` (no RainbowKit).

### 2.3 RabbyKit evaluated (not adopted)

`../rabbykit` = `@rabby-wallet/rabbykit` (ISC, `wagmi@2`/`viem@2`), a
RainbowKit-style connect kit with ~20 connectors. It **still uses WalletConnect**
(`helpers/getWalletConnectUri.ts` / `sharedWalletConnectConnectors`, most
connectors take `{projectId, metadata}`), so it replaces the modal but keeps
WalletConnect and reintroduces a vendor kit. It does **not** fit the thin
connector direction; only worth revisiting if a polished multi-wallet modal is
wanted later.

## 3. Target architecture

- **Providers**: `createConfig` (wagmi) with a **single external connector**
  (EIP-6963 / injected discovery) + the **in-app wallet provider**. No
  `RainbowKitProvider`, no WalletConnect.
- **Effective provider**: `useWalletProvider()` returns the in-app EIP-1193
  provider when the in-app wallet is unlocked, else the external one.
- **UI** (mirror learn.tg): `WalletSelector` (in-app vs external),
  `WalletDialog` (create/import/unlock), `WalletPanel`, `WalletEventListener`;
  `ConnectWalletButton` renders our own button (no `ConnectButton.Custom`).
- **Signing**: EIP-191 `personal_sign` through the effective provider; learn.tg
  KYC (`/api/verify`) unchanged. On-chain ops via viem `walletClient` built from
  the EIP-1193 provider (chain `celo` / `celoSepolia`, RPC `NEXT_PUBLIC_RPC_URL`).

## 12. Execution design (decided 2026-10-09, option A)

**Surface measured (small):** `wagmi` only in `providers/AppProvider.tsx`,
`contexts/WalletContext.tsx`, `hooks/useAutoConnect.ts`; `@rainbow-me/rainbowkit`
only in `AppProvider.tsx` and `components/ConnectWalletButton.tsx`; `useWallet()`
consumers: `osmmap/page.tsx` (`+isMiniPay`), `dashboard/page.tsx`,
`documenter/page.tsx`, `Footer.tsx`, `ConnectWalletButton.tsx`.

**New `useWallet()` API (keep the shape, add `provider`):**
`{ isConnected, address, effectiveAddress, chainId, provider, isInApp,
disconnect, donate, isTransacting, isProcessing }` — drop `isMiniPay`,
`phoneNumber`, `connectMiniPay`.

**`contexts/WalletContext.tsx`** — no wagmi. Effective provider = in-app ?? external:
- in-app: `useInAppWallet()` (`@pasosdejesus/m/wallet/next`); when
  `status === 'unlocked'`, `getProvider(NEXT_PUBLIC_RPC_URL)`.
- external: `useSyncExternalStore(subscribeExternalProvider,
  getExternalProviderSnapshot)` (`@pasosdejesus/m/wallet`).
- `address`: `provider.request({ method: 'eth_accounts' })` (uniform), refreshed
  on `accountsChanged`.
- `chainId`: from `NEXT_PUBLIC_NETWORK` (`celo` -> 42220, else 11142220).
- `disconnect`: `lock()` for the in-app; clears the address for the external.

**`providers/AppProvider.tsx`** — drop `WagmiProvider`/`RainbowKitProvider`;
call `configureInAppWallet({ dbName: 'sivel3-wallet', destinationsPrefix:
'sivel3-wallet', rpName: 'sivel.xyz' })`; keep `QueryClientProvider` +
`WalletProvider`.

**`components/ConnectWalletButton.tsx`** — no RainbowKit. A button opening a
dialog with `InAppWalletSetup` (no-wallet) / `InAppWalletUnlock` (locked), the
short address + "Desconectar" when connected, and an optional "billetera externa"
path (offered only when an external provider is detected).

**`lib/donate.ts` / `lib/buyPreAlert.ts`** — take the effective `provider` and
send with `provider.request({ method: 'eth_sendTransaction', params })`; remove
the MiniPay `ethereum.send` / calldata-extraction paths.

**Remove**: `hooks/useMiniPay.ts`, `hooks/useAutoConnect.ts`; deps
`@rainbow-me/rainbowkit`, `@rainbow-me/rainbowkit-siwe-next-auth`, `wagmi`
(keep `viem`, `@tanstack/react-query`); drop `isMiniPay` from
`app/[locale]/cases/osmmap/page.tsx`.

**Verify:** `make type` 0 errors, `make test` green, and a manual create/unlock +
external connect on `http://localhost:4000`.
