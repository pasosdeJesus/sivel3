# R-#59: Evaluate npm as pnpm replacement on OpenBSD

## Motivation

pnpm 12 will ship as a pure Rust native binary with no JavaScript fallback
and no OpenBSD target. While pnpm 10.34.5 works today, we need a contingency
plan for when it reaches EOL.

npm is the reference implementation bundled with Node.js and cannot go
native-only without breaking the Node.js distribution model. This REQ
evaluates whether npm can replace pnpm today on OpenBSD.

## Experiment: pnpm → npm migration (2026-07-24)

### Approach

1. Convert `package.json`: remove `packageManager`, remove `pnpm` field,
   move `pnpm.overrides` to npm `overrides` (same syntax), remove pnpm-specific
   `postinstall` scripts.
2. Update `Makefile`: `pnpm` → `npm run`.
3. Update `bin/dev`: `pnpm install` → `npm install`.
4. Delete `pnpm-lock.yaml`, `bin/fix-pnpm-store-path`.
5. Run `npm install --ignore-scripts` with overrides for WASM packages.

### Result

**npm migration blocked** — npm fails with platform CPU checks that pnpm
handles gracefully:

```
npm error EBADPLATFORM
npm error notsup Unsupported platform for @tailwindcss/oxide-wasm32-wasi@4.3.3:
wanted {"cpu":"wasm32"} (current: {"cpu":"x64"})
```

Multiple attempts were made:
- `npm install` (vanilla) — blocked by EBADPLATFORM
- `npm install --ignore-scripts` — blocked by EBADPLATFORM
- `npm install --no-optional` — blocked by EBADPLATFORM
- `npm install --force --legacy-peer-deps` — blocked by EBADPLATFORM
- Custom `.npmrc` with `optional=false` — blocked by EBADPLATFORM
- npm `overrides` with `npm:@tailwindcss/oxide-wasm32-wasi` — blocked

### Root cause

npm v11 strictly enforces the `cpu` field in `package.json` when checking
platform compatibility. `@tailwindcss/oxide-wasm32-wasi` declares
`"cpu": "wasm32"` which doesn't match OpenBSD's `x64`. Even though the
package is pure WASM and would work fine, npm refuses to install it.

pnpm is **more lenient** — it treats CPU mismatches in dependency metadata
as non-fatal warnings and installs the package anyway.

### Ironic finding

**pnpm is more OpenBSD-compatible than npm today.** The exact concern that
drove this investigation (pnpm going native) is the same pattern that makes
npm fail: strict platform checks. pnpm handles cross-platform WASM packages
gracefully; npm does not.

### Verdict

| Metric | pnpm 10.34 | npm 11 |
|--------|-----------|--------|
| OpenBSD install | ✅ Works | ❌ EBADPLATFORM |
| Cross-platform WASM | ✅ Lenient | ❌ Strict CPU checks |
| Native risk | ⚠️ v12 goes Rust-only | ✅ Bundled with Node |
| Long-term safety | ⚠️ EOL when v12 ships | ✅ Cannot go native |

**Recommendation:** Pin pnpm 10.34. Keep npm as documented fallback only if
the ecosystem fundamentally changes. The WASM platform check is a known npm
issue and may be resolved in future npm versions — re-evaluate then.
