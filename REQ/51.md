## Description

Replace off-chain endpoints with direct `SIVeL3PreAlertMarket` contract calls for **buy** and **convert**, closing the security gap in conversion and unifying the flow. The contract already implements both functions with `msg.sender` verification — this REQ wires them into the frontend and backend.

**Why on-chain:**
- **Convert:** `msg.sender` proves buyer identity cryptographically — eliminates impersonation risk (see #49 resolution). Compatible with MiniPay (`eth_sendTransaction`).
- **Buy:** replace calldata-stuffing workaround with proper `buyPreAlert(uint256)` call. The contract emits `PreAlertBought(id, buyer, amount)` — the backend verifies this event instead of parsing raw calldata.

**Current state (off-chain workaround):**
- Buy: frontend sends USDT via ERC-20 `transfer()` with `preAlertId` stuffed in calldata → backend parses calldata
- Convert: frontend calls `POST /api/pre-alerts/convert` with `buyer_wallet` string → no cryptographic proof

**Target state (on-chain):**
- Buy: frontend calls `buyPreAlert(id)` on contract (approve USDT first, or use permit)
- Convert: frontend calls `convertToAlert(id)` on contract (`msg.sender` === buyer)
- Backend: listens to `PreAlertBought` / `AlertConverted` events → updates DB

## Contract (already deployed — no changes needed)

`SIVeL3PreAlertMarket.sol` at `0x892373D6930dd38Cb54A28Ea8573e6d838570426` (Celo Sepolia) already implements:

```solidity
function buyPreAlert(uint256 preAlertId) external nonReentrant whenNotPaused {
    require(preAlerts[preAlertId].buyer == address(0), "Already bought");
    preAlerts[preAlertId].buyer = msg.sender;
    usdtToken.safeTransferFrom(msg.sender, address(this), PRICE_USDT);
    emit PreAlertBought(preAlertId, msg.sender, PRICE_USDT);
}

function convertToAlert(uint256 preAlertId) external whenNotPaused {
    require(preAlerts[preAlertId].buyer == msg.sender, "Not buyer");
    require(!preAlerts[preAlertId].converted, "Already converted");
    preAlerts[preAlertId].converted = true;
    emit AlertConverted(preAlertId, msg.sender);
}
```

### 3. Backend: replace calldata parsing with event verification

**`POST /api/pre-alerts/:id/buy`** — verify `PreAlertBought` event:

```typescript
async function verifyPreAlertPurchase(txHash: string): Promise<{
  valid: boolean
  buyer: string | null
  preAlertId: number | null
}> {
  const receipt = await client.getTransactionReceipt({ hash: txHash })
  // Find PreAlertBought(id, buyer, amount) event
  const event = decodeEventLog({
    abi: PREALERT_MARKET_ABI,
    data: receipt.logs[…].data,
    topics: receipt.logs[…].topics,
    eventName: 'PreAlertBought',
  })
  return { valid: true, buyer: event.args.buyer, preAlertId: Number(event.args.id) }
}
```

### 4. USDT Approval (MiniPay constraint)

MiniPay does **not** support `approve()`. Two options:

| Option | Works with MiniPay | Gas | UX |
|--------|-------------------|-----|-----|
| **A) `approve()` + `buyPreAlert()`** | ❌ | 2 txs | 2 confirmations |
| **B) USDT via `permit()`** | ❌ (requires `personal_sign`) | 1 tx | 1 confirmation |
| **C) `safeTransferFrom` with infinite approval** | ❌ (requires prior approval) | 1 tx | 1 confirmation |
| **D) Keep current `transfer()` pattern** | ✅ | 1 tx | 1 confirmation |

**Decision for MVP:** Keep the current `transfer()` + calldata-stuffing pattern for **buy** (option D), since `safeTransferFrom` requires `approve()` which MiniPay doesn't support. **Convert** can use the contract directly since it doesn't need USDT approval.
