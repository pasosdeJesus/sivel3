## Description

Polish the map layer experience for pre-alerts, alerts, and pre-cases with correct labels, richer detail panels, filter integration, and counts.

## Requirements

### 1. Correct Labels by Status

| Status | Label |
|--------|-------|
| `pending` | Pre-Alert |
| `reserved` | Pre-Alert (bought) |
| `converted` | Alert |
| `pending_reward` | Alert (under review) |
| `paid` | Pre-Case |
| `rejected` | Alert (rejected) |

The modal title should reflect the status, e.g., "Pre-Case #37" instead of always "Pre-Alert #37".

### 2. Pre-Case Detail Panel

When viewing a `paid` pre-alert, show:
- **Score** and **feedback** from the documenter
- **Buyer wallet** (the citizen who purchased)
- **Documenter wallet** (who scored it)
- **Citizen notes** (improvements added before conversion)

### 3. Map Filters

Apply the existing Filter criteria (date range, department, category) to pre-alerts/alerts/pre-cases. Currently filters only affect the "Casos" layer. Extend to the pre-alert layer.

### 4. Counts Integration

Add pre-alert/alert/pre-case counts to the Counts popover, filtered by current criteria:

| Metric | What it counts |
|--------|---------------|
| Pre-Alerts | `status = 'pending'` |
| Purchased (not commented) | `status = 'reserved'` with `citizen_notes IS NULL` |
| Alerts | `status IN ('converted', 'pending_reward')` |
| Pre-Cases | `status = 'paid'` |

### 5. Show All Matching Pre-Alerts

When viewing the pre-alert layer, show ALL pre-alerts matching the filter criteria — not just the market + user's own. Users should see the full ecosystem activity. Filters narrow by time, region, and department.

### 6. Full-Screen Detail View (Post-MVP)

Replace the small sidebar card with a dedicated page/screen for pre-alerts, alerts, and pre-cases. Full JSON data, source links, conversion history, and documenter trail.

---

## Acceptance Criteria

- [ ] Modal title shows correct type: Pre-Alert, Alert, or Pre-Case
- [ ] Pre-Case panel shows score, feedback, buyer, documenter, citizen notes
- [ ] Map filters (date, department) apply to pre-alert layer
- [ ] Counts popover shows pre-alert/alert/pre-case counts
- [ ] Pre-alert layer shows all matching pre-alerts (not limited to user's own)
