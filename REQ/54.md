# R-#54: Test contracts on OpenBSD using m/edr (@ethereumjs/vm)

## Description

`bin/m contract:test` is an EDR replacement for OpenBSD/adJ that uses `@ethereumjs/vm` (pure JavaScript) instead of `@nomicfoundation/edr` (Rust/napi-rs). Napi-rs has no OpenBSD support. This enables running Hardhat-compatible contract tests on OpenBSD.

Currently, sivel3 has 3 Hardhat test suites that **cannot run** on OpenBSD due to missing EDR binary:

| Test file | Tests |
|-----------|-------|
| `SIVeL3PreAlertMarket.test.ts` | 26 |
| `SIVeL3RewardEscrow.test.ts` | 16 |
| `PasosDeJesusCredentials.test.ts` | ? |

## Tasks

### 1. Adapt test imports

Tests must change from native Hardhat imports to `contract:test`-compatible format:

```typescript
// ❌ Native Hardhat (does NOT work on OpenBSD)
import { ethers } from "hardhat"

// ✅ contract:test compatible
const { ethers } = (globalThis as any).hre
```

### 2. Run tests with contract:test

```bash
cd apps/hardhat
bin/m contract:test
```

### 3. Report missing EDR features

As tests run, features not yet implemented in `contract:test` will produce errors like `"not implemented on OpenBSD: <feature>"`. Report these as they surface so they can be added to `m/edr`.

Common missing features may include:
- `console.log` in Solidity (source-mapped stack traces)
- Coverage instrumentation (`hardhat coverage`)
- Gas reporting (`hardhat test --gas`)
- Mainnet forking edge cases

### 4. Implement missing features in m/edr (iterative)

For each missing feature surfaced by the tests:

1. Identify which EDR API call Hardhat is making
2. Implement the equivalent using `@ethereumjs/vm` APIs
3. Add fallback or graceful degradation if the feature is complex
4. Re-run tests to confirm fix

## Dependencies

- Requires `@pasosdejesus/m` with `contract:test` command
- Requires `@ethereumjs/vm` v10 (now a dependency of m)
- **pnpm override required** — wagmi pulls `@ethereumjs/tx@4` → `util@8`, `common@3`. See fix below.

### pnpm override fix

Add to `apps/nextjs/package.json`:

```json
"pnpm": {
  "overrides": {
    ...existing overrides...,
    "@ethereumjs/common": "^10.1.2",
    "@ethereumjs/util": "^10.1.2",
    "@ethereumjs/tx": "^10.1.2"
  }
}
```

Then `pnpm install`.

### 2026-07-03 — Debugging `bin/m contract:test` on OpenBSD

**Errores encontrados y soluciones:**

| # | Error | Causa | Solución |
|---|-------|-------|----------|
| 1 | `Hardfork with name cancun not supported` | `createRequire(cwd/node_modules/...)` resolvía `@ethereumjs/common@3` (CJS, de wagmi) en vez de v10 | Usar `ethereumjs-bridge.cjs` que resuelve desde `m/package.json` |
| 2 | `Cannot use 'in' operator to search for 'eips' in undefined` | `mergeForkIdTransition`/`paris` y `constantinople`/`petersburg` con mismo bloque → bug en `Common.setHardfork()` | Bloques distintos: merge=15537393, paris=15537394, constantinople=7279999, petersburg=7280000 |
| 3 | `Cannot find module './ethereumjs-bridge.cjs'` | `npm run build` incompleto (solo `tsc`, falta copiar archivos .cjs) | Correr build completo (`rm -rf dist && npx tsc && cp ...`) |

**Cambios en `@pasosdejesus/m`:**
- `src/tasks/contract-test/edr-provider.ts`:
  - Bridge CJS: todos los `@ethereumjs/*` imports vía `ethereumjs-bridge.cjs`
  - Bloques no duplicados en Mainnet inline config
  - `defaultHardfork: 'chainstart'`, `hardfork: Hardfork.Chainstart` (evita bug `setHardfork`)
- `src/tasks/contract-test/hre-mock.ts`:
  - `ethers.id()` implementado con `viem.keccak256`
  - `ethers.ZeroAddress`, `ZeroHash`, `MaxUint256` añadidos
- `dist/tasks/contract-test/edr-provider.js`: recompilado con los cambios

**Resultado actual (2026-07-03):**

✅ `'eips' in undefined` resuelto — `bin/m contract:test` ya ejecuta las 4 suites
✅ Common se crea con `chainstart`, luego `setHardfork(Cancun)` exitoso
❌ 6 fallos: `VM Exception: invalid opcode` al desplegar contratos via `eth_sendTransaction`

Los fallos restantes son de compatibilidad EVM: `@ethereumjs/vm` rechaza algunos opcodes de Solidity 0.8.24 incluso con hardfork Cancun activo. Esto puede requerir:
- Verificar que `PUSH0` esté en los EIPs de la hardfork Cancun en el config inline
- Probar con `hardfork: 'shanghai'` en vez de `cancun`
- Investigar si `@ethereumjs/vm@10.1.2` tiene un bug con `PUSH0`

**Cambios totales en `@pasosdejesus/m` (3 archivos):**
- `edr-provider.ts`: bridge CJS, hardforks reducidos a chainstart+cancun, setHardfork(Cancun) en init()
- `hre-mock.ts`: ethers.id() con viem.keccak256, ZeroAddress/ZeroHash/MaxUint256
- `ethereumjs-bridge.cjs`: sin cambios (ya existía)

**Bugs fixed in `@pasosdejesus/m`:**
1. `hasHardhatDir` detection — added `../hardhat` path
2. `contract:test` handler — wasn't passing CLI arg to `runContractTest()`
3. `@ethereumjs/*` moved from `devDependencies` to `dependencies`
4. `createRequire` now resolves from consumer's `node_modules/@pasosdejesus/m/package.json`
5. Inline `Mainnet` chain config with `eips: []` — avoids importing from `@ethereumjs/common` (v3/v10 type conflict)
6. CJS bridge approach abandoned — ESM `createRequire` from `process.cwd()` is the correct fix

**Root cause:** pnpm hoists `@ethereumjs/util@8` (from wagmi → tx@4) above `@ethereumjs/util@10` (needed by m).
`@ethereumjs/vm@10` internally requires `@ethereumjs/util` and gets v8 which lacks `keccak256`.

**Next:** apply pnpm override in sivel3 → `pnpm install` → retry.
