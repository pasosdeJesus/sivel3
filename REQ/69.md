## Description

The public map is free and anonymous (a founding principle), but today it ships the whole case
index in one request. This requirement makes the map serve only what it draws: an identifier,
a latitude and a longitude, bounded by the viewport and aggregated into cells when zoomed out,
with cache headers and per-IP limits. It does not charge anything and it does not add wallet
quotas: that is https://gitlab.com/pasosdeJesus/sivel3/-/issues/17.

## Current state (measured 2026-11-23)

| Site | `GET /api/cases/counts` | `GET /api/cases/datos-osm` | Headers |
|------|-------------------------|----------------------------|---------|
| Dev `sivel.xyz:9001` | 48,187 cases, 95,639 victims, 143,436 acts | 39,866 markers, **5.55 MB, 4.6 s**, no pagination | no `Cache-Control`, no `ETag` |
| Production `sivel.xyz` | 531 cases | 438 markers, 0.06 MB | no `Cache-Control`, no `ETag` |

- `apps/web/app/api/cases/datos-osm/route.ts:108-125` returns
  `{ respuesta: { "<id>": { latitud, longitud, departamento, municipio, fecha } } }`.
- The map consumes only the key and `latitud`/`longitud`
  (`apps/web/components/mapa/MapComponent.tsx:195-206`); the popup loads the detail endpoint
  (`MapComponent.tsx:110-115`), which is where `departamento`, `municipio` and `fecha` come from.
- No rate limiting exists in `app/`, `lib/` or `proxy.ts`.
- `GET /api/cases/[id]` returns victim names to anonymous callers and has no limit.

The 48,187 (counts) and 39,866 (markers) difference is by design: the map plots only cases with
coordinates and at least one act (`datos-osm/route.ts:46-52`).

## Goal

Keep the map public, but stop serving the corpus as a single downloadable file, and make the
response proportional to what the screen can draw.

## Scope

1. **Minimal payload.** Each marker carries only `latitud` and `longitud`; the case id stays as
   the object key (the map uses it to open the detail). Drop `departamento`, `municipio` and
   `fecha` from this response: they are unused and they are the part that makes the JSON a
   usable dataset.
2. **Viewport.** Accept `bbox=minLng,minLat,maxLng,maxLat`; without it, the endpoint serves only
   the first zoom level's aggregates (never the whole country as individual markers).
3. **Server-side aggregation.** With `zoom` below a threshold, group cases into cells and return
   `{ celdas: [{ latitud, longitud, n }] }`; at high zoom return individual markers
   (`{ respuesta: { "<id>": { latitud, longitud } } }`). Cell size by zoom (initial: 0.5° below
   zoom 6, 0.1° below 9, 0.02° below 11, markers from zoom 11). The filters
   (`fechaini`, `fechafin`, `departamento_id`, `presponsable_id`, `categoria_id`) apply before the
   aggregation, so the sum of `n` matches `/api/cases/counts`.
4. **Response cap.** Maximum 5,000 rows per response; beyond that, require a tighter `bbox` or a
   lower zoom and answer `413` with the cap.
5. **Cache.** `Cache-Control: public, s-maxage=300, stale-while-revalidate=60` and `ETag` with
   `304` on `If-None-Match`. The data changes slowly; the map must not re-download it on every
   pan.
6. **Read limits (technical).** 60 req/min per IP for `/api/cases/datos-osm` and
   `/api/cases/counts`; `429` with `Retry-After`. For `/api/cases/[id]`: 120 req/min per IP and
   **no victim names for anonymous callers**. Wallet quotas and `402` stay in
   https://gitlab.com/pasosdeJesus/sivel3/-/issues/17.
7. **Consumers and tests.** `MapComponent` sends `bbox`/`zoom` and draws cells as cluster markers;
   update `tests/cases-routes.test.ts`, `e2e/smoke/public-api.spec.mjs` (shape) and
   `apps/web/doc/API.md`.

## Out of scope

- Credits, wallets, free monthly quotas and `402` responses
  (https://gitlab.com/pasosdeJesus/sivel3/-/issues/17).
- Pre-alert layer, labels, filters UI and counts popover
  (https://gitlab.com/pasosdeJesus/sivel3/-/issues/55).
- A bulk export endpoint: if it is ever offered, it is billable (issue 17).

## Acceptance criteria

- [ ] `GET /api/cases/datos-osm` no longer returns `departamento`, `municipio` or `fecha`.
- [ ] A request without `bbox` never returns individual markers for the whole country.
- [ ] Low zoom returns cells whose `n` sums to the filtered total of `/api/cases/counts`.
- [ ] No response exceeds 5,000 rows; a wider request gets `413` with the cap.
- [ ] Dev-site payload for zoom 5 over Colombia is under 200 KB and answers in under 1 s once warm.
- [ ] `ETag` produces `304` on an unchanged request; `Cache-Control` is present.
- [ ] The 61st request in a minute from one IP gets `429` with `Retry-After`.
- [ ] `/api/cases/[id]` omits victim names for anonymous callers and is limited per IP.
- [ ] The map still plots, clusters, opens the popup and keeps the filters working.

## Implementation (2026-11-23)

Done in the working tree; the real check is the next deploy.

- `apps/web/lib/mapData.ts`: `parseBbox`, `parseZoom`, `cellStepForZoom`, `MAX_ROWS = 5000`.
- `apps/web/lib/rateLimit.ts`: in-memory fixed window per IP (`x-forwarded-for`, then
  `x-real-ip`), `429` with `Retry-After`. Single-process store, documented limitation.
- `app/api/cases/datos-osm/route.ts`: minimal payload (`id` + coordinates), `bbox`/`zoom`,
  aggregation into cells (0.5°, 0.1°, 0.02°), `413` above 5,000 rows, `Cache-Control` and
  `ETag`/`304`, 60 req/min per IP. Markers are skipped when a coordinate is null.
- `app/api/cases/counts/route.ts`: 60 req/min per IP.
- `app/api/cases/[id]/route.ts`: 120 req/min per IP and `victimas_count` instead of victim names
  (`PRINCIPLES.md` §2).
- `components/mapa/MapComponent.tsx`: sends `bbox`/`zoom`, draws cells with their count (click
  zooms in), reloads on `moveend` (debounced), popup shows the victims count.
- Tests: `tests/cases-routes.test.ts` (13 green) covers markers, cells, filters, `304`, `400`,
  `413`, `429` and the detail shape; the smoke keeps accepting the old `respuesta` envelope.
  `make type`, `make type-check-tests` and `make test` (190 tests) green.
- SQL validated against the local database (531 cases, 438 markers): the aggregation groups by
  select ordinals (PostgreSQL does not fold the parameterised expressions) and the cells sum to
  438 at 0.5°, 0.1° and 0.02°.
