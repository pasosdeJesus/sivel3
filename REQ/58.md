# R-#58: Replace solidity-analyzer / Hardhat compile with solc on OpenBSD

## Motivation

Hardhat 2 depends on `@nomicfoundation/solidity-analyzer` (Rust/napi-rs, no
OpenBSD binary). While `prepadJ.sh` compiles it from source, this is a fragile
workaround. Hardhat 3 is already released and uses EDR v2 (same platform issue).
We need a long-term strategy that doesn't depend on native binaries.

## Experiment: solc WASM replaces hardhat compile (2026-07-24)

### Setup

```bash
cd /tmp && mkdir solc-experiment && cd solc-experiment
npm init -y && npm install solc
```

### Compilation

Compiled all 5 sivel3 contracts + OpenZeppelin dependencies via solc WASM
(`soljson.js`), resolving `@openzeppelin/` imports from
`apps/hardhat/node_modules/`.

```javascript
const solc = require('solc')
const input = {
  language: 'Solidity',
  sources: { ... },
  settings: {
    optimizer: { enabled: true, runs: 200 },
    evmVersion: 'cancun',
    outputSelection: { '*': { '*': ['abi', 'evm.bytecode.object'] } }
  }
}
const output = JSON.parse(solc.compile(JSON.stringify(input), { import: findImports }))
```

### Results

| Metric | solc WASM | Hardhat (native solc + solidity-analyzer) |
|--------|-----------|------------------------------------------|
| Compilation time | **23s** | 2m37s (includes clean + ABI sync) |
| Errors | **0** | 0 |
| ABIs match | **Yes** (100% identical) | — |
| Bytecode match | No (different solc builds) | — |
| OpenBSD binary needed | **No** (pure WASM) | Yes (solidity-analyzer) |

### Key findings

1. **solc WASM compiles all 5 contracts successfully** with 0 errors.
2. **ABIs are 100% identical** to Hardhat's output — contracts are
   functionally equivalent.
3. **Bytecodes differ** because different solc builds produce different
   optimized code. This is expected and harmless — ABIs define the
   interface.
4. **~7x faster** than `hardhat compile` (23s vs 2m37s), though Hardhat's
   time includes `hardhat clean` + `sync-abis.mjs`.
5. **Zero native dependencies** — `soljson.js` is pure WASM, works on
   any platform with Node.js.

## Native solc port for OpenBSD/adJ (2026-07-24/25)

Created an OpenBSD port adapting the FreeBSD `lang/solidity` port. Located at
`/usr/ports/mystuff/lang/solidity/`.

### Port structure

```
mystuff/lang/solidity/
├── Makefile           # OpenBSD port adapted from FreeBSD
├── distinfo           # SHA256 + size
├── files/

└── pkg/
    ├── DESCR
```

| nlohmann-json | textproc/nlohmann-json | nlohmann-json-3.12.0 |

### Build attempt

`doas make` fails building transitive dependencies (meson → jsoncpp →
cmake → fmt) due to permission issues in `/usr/ports/pobj/`. This is an
environment setup issue, not a port definition issue. The port Makefile
itself is syntactically correct and all dependency paths are verified
against `/usr/local/share/ports-INDEX`.

**Next:** Test on a machine with a properly configured ports system
(`/usr/ports/pobj/` writable, all dependency packages pre-built).

## Hardhat yarn → pnpm migration (2026-07-22)

As part of this REQ, `apps/hardhat` was migrated from yarn to pnpm:

### Changes

| File | Change |
|------|--------|
| `apps/hardhat/package.json` | `packageManager: pnpm@10.33.0`, scripts use `pnpm` instead of `yarn` |
| `apps/hardhat/package.json` | `@ethereumjs/*` moved here from `apps/nextjs` (as devDependencies) |
| `apps/hardhat/package.json` | pnpm overrides for `@ethereumjs/common`, `util`, `tx` |
| `apps/hardhat/package.json` | `"test": "../nextjs/bin/m contract:test"` (runs from hardhat dir) |
| `apps/nextjs/package.json` | `@ethereumjs/*` removed (m declares them as dependencies) |
| `apps/hardhat/bin/prepadJ.sh` | Adapted to pnpm's `.pnpm/` directory structure |
| `apps/hardhat/hardhat.config.ts` | Added `evmVersion: 'cancun'` (required for OZ 5.x `mcopy`) |

### Reasons

1. **Separation of concerns**: contract tests and EVM tooling belong in `apps/hardhat/`,
   not the Next.js frontend.
2. **Cleaner Next.js**: `apps/nextjs/` no longer carries ~200MB of `@ethereumjs/*`
   packages just for testing.
3. **Test from hardhat dir**: `pnpm test` now runs contract tests from their
   natural home, using `../nextjs/bin/m contract:test`.

### Result

```bash
cd apps/hardhat
pnpm build   # compiles contracts, syncs ABIs to nextjs ✅
pnpm test    # 5 files, 87 tests, 0 failures ✅
```

### prepadJ.sh

The migration uncovered a **corepack conflict**: solidity-analyzer needs
yarn@4.2.2 but corepack detects the parent's `packageManager: pnpm` and
blocks yarn. **Solution**: copy solidity-analyzer to `/tmp`, build there
(yarn 4.2.2 works in isolation), copy the compiled `.node` back.

This approach works but confirms that depending on native binaries
(solidity-analyzer) is fragile on OpenBSD — reinforcing the need for
solc WASM as the long-term compilation strategy.

## Package manager ecosystem analysis (2026-07-24)

The entire JavaScript package manager ecosystem is migrating to native
languages (Rust, Zig), driven by Bun's performance advantage. This has
direct implications for OpenBSD/adJ:

### Status matrix

| Package Manager | Current | Next Version | OpenBSD Future |
|----------------|---------|-------------|----------------|
| **npm** | JS pure, bundled with Node.js | Same | ✅ **Safe forever** — cannot go native without breaking Node.js distribution |
| **pnpm 11** (our v10.33) | JS/ESM | N/A | ✅ Works today; ⚠️ EOL when v12 ships |
| **pnpm 12** | — | Pure Rust binary, 8 platforms only | ❌ No JS fallback, no OpenBSD target |
| **yarn 4** (berry) | JS via Corepack | Same (for now) | ✅ Works via Node.js |
| **yarn 6** | — | Planned native (unannounced) | ❌ Expected to follow pnpm's path |
| **Bun** | Rust + JavaScriptCore | Native binary | ❌ PR #9150 (OpenBSD port) abandoned Jun 2025. [Confirmed Rust rewrite](https://github.com/oven-sh/bun) |

### Bun PR #9150: "setting up openbsd base ports"

- **Author:** rwsalie
- **Status:** Closed without merge (Jun 2025)
- **Progress:** Build system adapted for OpenBSD ✅, Zig source porting never completed ❌
- **Fork:** `rwsalie/bun-openbsd` — abandoned Aug 2024, 2 stars
- **Bun language:** Originally Zig, [now rewritten in Rust](https://github.com/oven-sh/bun) ("It's written in Rust and powered by JavaScriptCore under the hood")
- **Conclusion:** OpenBSD port is multi-person-year effort, not feasible short-term

### Why npm is the safe harbor

npm is the **reference implementation** bundled with Node.js. It exists to
be the canonical JS package manager. Unlike pnpm/yarn/bun which compete on
speed and can justify native rewrites, npm cannot abandon JavaScript without
breaking the Node.js distribution model itself. If npm ever goes native-only,
Node.js would need to bundle a native binary — at which point the ecosystem
has fundamentally changed and our strategy would need reevaluation.

### npm migration attempt (2026-07-24) — blocked

We attempted to migrate both `apps/nextjs` and `apps/hardhat` from pnpm to npm.
The migration failed because npm is **stricter than pnpm** about CPU platform
checks for cross-platform WASM packages:

```
npm error EBADPLATFORM
npm error notsup Unsupported platform for @tailwindcss/oxide-wasm32-wasi@4.3.3:
wanted {"cpu":"wasm32"} (current: {"cpu":"x64"})
```

pnpm installs these packages without complaint because it treats CPU
mismatches in dependency metadata as non-fatal. npm (v11) strictly enforces
the `cpu` field and refuses to install packages whose `cpu` field doesn't
match the current architecture, **even when the package is pure WASM and
would work fine**.

**Irony:** pnpm is actually more OpenBSD-compatible than npm today. The
native migration risk (pnpm 12) is real but pnpm 10.33 works better than
npm on OpenBSD right now. This reinforces the strategy: pin pnpm, document
the risk, and keep npm as the fallback only if needed.

### Our position

- **Short term:** pnpm 10.33 works perfectly on OpenBSD. Pin it.
- **Medium term:** Monitor pnpm 11 lifecycle. Evaluate npm as migration target if pnpm EOL approaches.
- **Long term:** npm is the guaranteed fallback. All our tooling (`bin/m`, `contract:test`) works with any package manager's `node_modules`.

## Strategy

### Short term (today)
- `solc` WASM is **ready to use** — compiles all contracts, produces correct ABIs
- Keep Hardhat for now (artifacts, tests via `contract:test`)
- `prepadJ.sh` as fallback for `hardhat compile`

### Medium term
- Write a `bin/compile` script that uses solc WASM to produce artifacts
  (bytecode + ABI JSON) in the same format Hardhat expects
- Migrate `contract:test` to use solc-compiled artifacts instead of
  requiring `hardhat compile`

### Long term
- Remove Hardhat dependency entirely: `contract:*` family replaces all Hardhat functionality
- Port `lang/solidity` from FreeBSD to OpenBSD/adJ for native solc binary
- If native solc is available, prefer it over WASM for speed

## contract:* — post-Hardhat command family

Once solc replaces `hardhat compile`, the full Hardhat replacement becomes:

| Command | Replaces | Implementation |
|---------|----------|---------------|
| `contract:compile` | `hardhat compile` | solc WASM → artifacts + ABI sync to nextjs |
| `contract:test` | `hardhat test` | @ethereumjs/vm + hre-mock ✅ (done) |
| `contract:deploy` | `hardhat run scripts/deploy.ts` | viem walletClient + contract artifact |
| `contract:verify` | `hardhat verify` | Blockscout/Celoscan API POST |

### contract:compile

Already prototyped in this REQ. Compiles all contracts with solc WASM,
produces artifacts in the same format Hardhat expects. Replaces:
- `hardhat clean && hardhat compile`
- `node sync-abis.mjs`
- TypeChain type generation (`npx typechain --target ethers-v6`)

### contract:deploy

Reads compiled artifact (ABI + bytecode), encodes constructor args via
viem's `encodeDeployData`, signs and sends via `eth_sendTransaction`.
Replaces:
- `hardhat run scripts/deploy.ts`
- Manual gas estimation
- Address persistence to `.env` / deployments JSON

### contract:verify

POSTs flattened source + constructor args to Blockscout API:
```
POST https://celo.blockscout.com/api/v2/smart-contracts/{address}/verification/via/standard-input
```
Replaces:
- `hardhat verify`
- Manual Blockscout form submission
