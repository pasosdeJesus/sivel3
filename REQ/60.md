# R-#60: Regression in EdrProvider — emergencyWithdraw reverts after m update

## Summary

`SIVeL3RegionalDonationV2.test.ts` passed 6/6 with
`@pasosdejesus/m` at archive `_6f0fe345`. After a gitlab update to
archive `_90facacafe`, 1 test regressed: `emergencyWithdraw` reverts with
`VM Exception: revert`.

### Contract code (SIVeL3RegionalDonationV2.sol)

```solidity
function emergencyWithdraw() public onlyOwner nonReentrant {
    uint256 totalBalance = donationToken.balanceOf(address(this));
    require(totalBalance > 0, "No funds to withdraw");
    donationToken.safeTransfer(owner(), totalBalance);
    emit EmergencyWithdrawal(owner(), totalBalance);
}
```

## Investigation

- ✅ Test works in isolation (single file): still fails → not test ordering
- ✅ Test passed with m archive `_6f0fe...` → regression in m, not in sivel3
- ✅ Other `emergencyWithdraw` tests pass (SIVeL3RewardEscrow) → not a generic
  `emergencyWithdraw` issue
- ✅ `withdraw` works before `emergencyWithdraw` in same test → reentrancy guard
  is properly reset, not a `nonReentrant` state issue
- ✅ Contract has positive USDT balance at time of call (verified via
  `mockUSDT.balanceOf(contract)` assertion passing just before)
- ⚠️ Revert reason is empty (`VM Exception: revert` without message)

## Suspected causes

1. **eth_call inside eth_sendTransaction** — `emergencyWithdraw` calls
   `donationToken.balanceOf(address(this))` as an internal `eth_call` during
   the transaction. The new EdrProvider may return 0 for this nested call.
2. **Gas estimation** — `emergencyWithdraw` may need more gas than the
   default 5M in the new EdrProvider commit.
3. **Owner account state** — owner account nonce or balance may be
   inconsistent after the `withdraw` call.
