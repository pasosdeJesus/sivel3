The `RegionalDonation.sol` contract is already deployed and working (as seen in the API endpoint `/api/regions/[id]/balance`). However, the frontend lacks a user-friendly way for donors to actually donate to a specific region. This issue covers building the donation UI and integrating it with the existing contract.

**Tasks:**
- [x] On the region page (or as a sidebar on the map), add a "Donate to this Region" button.
- [x] Create a donation modal that:
    - Shows the region's name and current balance (fetched from the API).
    - Allows the user to enter an amount in USD (or USDT).
    - Requires the user to connect their wallet (if not already connected).
    - Handles the USDT approval (the user must approve the `RegionalDonation` contract to spend their USDT). *(Simplified: single USDT `transfer()` with regionId in calldata, no approve step — MiniPay compatible)*
    - Calls the `donate(regionId, amount)` function on the `RegionalDonation` contract.
- [x] After a successful donation, refresh the displayed balance for the region.
- [x] Add a "Recent Donations" list on the region page, showing the last few donations (by listening to the `DonationReceived` event from the contract). *(via leaderboard endpoint)*

**Acceptance Criteria:**
- [x] A user can donate USDT to a specific region (Colombia or Israel/Palestine) from the frontend.
- [x] The donation flow handles USDT approval and the donation transaction in sequence. *(Single-transfer pattern — no approve needed)*
- [x] The user sees a confirmation message upon success.
- [x] The region's balance updates immediately (or after a short delay).
- [x] The contract's events are used to display a history of donations (optional, but good for transparency). *(via leaderboard + on-chain events)*

**Resolution (2026-06-22):** Closed as completed. Implemented via `lib/donate.ts` (MiniPay + MetaMask), `RegionalDonationV2` contract, regional balance API, leaderboard, Learning Points integration, and confetti UX.
