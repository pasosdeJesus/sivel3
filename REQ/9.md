# R-#9: R-#9 Implement Role-Based SBTs for Documenters and Validators

SIVeL 3 uses **Soulbound Tokens (SBTs)** to manage roles and permissions within the ecosystem. These SBTs are non‑transferable credentials that grant access to specific actions (e.g., verifying alerts, accessing dashboards, publishing pre‑alerts).

The **`PasosDeJesusCredentials` contract** (deployed in #26) already provides all the necessary infrastructure:
- ERC-1155 with `AccessControl`
- Soulbound flag (`isSoulbound`)
- Role‑based minting (`MINTER_ROLE`)
- Metadata and image pipeline
- Off‑chain cache (`credential_metadata`)

**This issue focuses on the integration and configuration** of the existing contract for role management in `sivel.xyz`. No new contract is required.

---

## Key Design Decisions

| Decision | Rationale |
| :--- | :--- |
| **Reuse `PasosDeJesusCredentials`** | Avoids deploying a separate contract. All credentials (SBTs) live in one place. |
| **`isSoulbound = true` for all roles** | Documenter, Validator, and Agent SBTs must be non‑transferable. |
| **Role identifiers as dynamic `tokenId`s** | Each role gets a `tokenId` assigned sequentially by the contract at registration time. Record the returned `tokenId`. |
| **Minting restricted to `MINTER_ROLE`** | Only the backend wallets of `sivel.xyz` can mint new role SBTs. |
| **Off‑chain role resolution** | The frontend calls an API endpoint (`/api/user/role`) that reads the SBT balance from the contract. |
| **Existing CLI for admin tasks** | All configuration (registering role types, minting) is done via `bin/m credentials`. |
| **`--chain` flag required for minting** | For now, the CLI explicitly requires `--chain celo` to specify the network. Future unification with `learn.tg` may remove this. |

## Tasks

### 1. Register Role Types (via `bin/m credentials`)

Use the `register-type` command from the unified CLI (provided by `@pasosdejesus/m`) to create each role type on the **Celo contract**. Note that `tokenId`s are assigned sequentially.

```bash
cd apps/nextjs

# Register Documenter role
bin/m credentials register-type \
  --site sivel.xyz \
  --type role \
  --display "SIVeL 3 Documenter" \
  --soulbound true \
  --icon "./public/img/roles/documenter.svg"

# Register Publishing Validator role
bin/m credentials register-type \
  --site sivel.xyz \
  --type role \
  --display "SIVeL 3 Publishing Validator" \
  --soulbound true \
  --icon "./public/img/roles/validator.svg"

# Register AI Agent role
bin/m credentials register-type \
  --site sivel.xyz \
  --type role \
  --display "SIVeL 3 AI Agent" \
  --soulbound true \
  --icon "./public/img/roles/agent.svg"

# Register Administrator role (optional; the deployer wallet already has DEFAULT_ADMIN_ROLE)
bin/m credentials register-type \
  --site sivel.xyz \
  --type role \
  --display "SIVeL 3 Administrator" \
  --soulbound true \
  --icon "./public/img/roles/admin.svg"
```

**Important:** After each command, record the `tokenId` returned by the CLI. You will need these `tokenId`s for the next steps and for the `ROLE_TOKEN_IDS` mapping in your code.

### 2. Grant `MINTER_ROLE` to Backend Wallets

Ensure that the backend wallet (the `PRIVATE_KEY` used by `sivel.xyz`) has the `MINTER_ROLE` on the **Celo contract**.

```bash
bin/m credentials grant-minter --network celo --address <BACKEND_WALLET_ADDRESS>
```

### 3. Mint Role SBTs to Initial Wallets

Use the `mint` command with the `--network celo` flag to assign roles to the initial set of users (documenters, validators, agent wallet).

```bash
# Mint Documenter SBT using its recorded tokenId
bin/m credentials mint --network celo --token-id <DOCUMENTER_TOKEN_ID> --to <DOCUMENTER_WALLET_ADDRESS>

# Mint AI Agent SBT to the agent wallet (from #36)
bin/m credentials mint --network celo --token-id <AI_AGENT_TOKEN_ID> --to <AGENT_WALLET_ADDRESS>
```

### 4. Backend: Role Checking Service

- [ ] **Create `lib/roles.ts`** in `apps/nextjs`:

```typescript
import { createPublicClient, http } from 'viem';
import { celo } from 'viem/chains';
import { getContract } from 'viem';
import { CREDENTIALS_ABI } from '@/lib/abis'; // ABI from #26

// Update these constants with the tokenIds recorded from step 1
export const ROLE_TOKEN_IDS = {
    DOCUMENTER: <TOKEN_ID_DOCUMENTER>,
    VALIDATOR: <TOKEN_ID_VALIDATOR>,
    AI_AGENT: <TOKEN_ID_AI_AGENT>,
    ADMINISTRATOR: <TOKEN_ID_ADMINISTRATOR>,
} as const;

export async function getUserRole(address: string): Promise<keyof typeof ROLE_TOKEN_IDS | null> {
    const publicClient = createPublicClient({
        chain: celo,
        transport: http(process.env.NEXT_PUBLIC_RPC_URL),
    });

    const contract = getContract({
        address: process.env.NEXT_PUBLIC_CREDENTIALS_CONTRACT_ADDRESS as `0x${string}`,
        abi: CREDENTIALS_ABI,
        client: publicClient,
    });

    for (const [roleName, tokenId] of Object.entries(ROLE_TOKEN_IDS)) {
        const hasRole = await contract.read.hasCredential([address as `0x${string}`, tokenId]);
        if (hasRole) return roleName as keyof typeof ROLE_TOKEN_IDS;
    }
    return null;
}
```

- [ ] **Create an API endpoint `GET /api/user/role`**:

```typescript
import { NextRequest, NextResponse } from 'next/server';
import { getUserRole } from '@/lib/roles';

export async function GET(req: NextRequest) {
    const { searchParams } = new URL(req.url);
    const address = searchParams.get('address');
    if (!address) return NextResponse.json({ error: 'Missing address' }, { status: 400 });

    const role = await getUserRole(address);
    return NextResponse.json({ role });
}
```

### 5. Protect API Routes with Role Checking

- [ ] **Create a helper function `requireRole(role)`** in `lib/auth.ts`:

```typescript
import { NextRequest } from 'next/server';
import { getUserRole } from './roles';

export async function requireRole(req: NextRequest, requiredRole: keyof typeof ROLE_TOKEN_IDS) {
    const walletAddress = req.headers.get('x-wallet-address'); // Sent by frontend
    if (!walletAddress) throw new Error('Unauthorized');

    const userRole = await getUserRole(walletAddress);
    if (userRole !== requiredRole) throw new Error('Forbidden');
    return true;
}
```

- [ ] **Protect the verification API** (e.g., `POST /api/alerts/verify`):

```typescript
import { requireRole } from '@/lib/auth';

export async function POST(req: NextRequest) {
    await requireRole(req, 'DOCUMENTER');
    // ... verification logic
}
```

### 6. Frontend: Conditional UI Rendering

- [ ] **Create a hook `useUserRole()`**:

```typescript
// hooks/useUserRole.ts
import { useAccount } from 'wagmi';
import { useEffect, useState } from 'react';

export function useUserRole() {
    const { address } = useAccount();
    const [role, setRole] = useState<string | null>(null);

    useEffect(() => {
        if (!address) return;
        fetch(`/api/user/role?address=${address}`)
            .then(res => res.json())
            .then(data => setRole(data.role));
    }, [address]);

    return role;
}
```
