## Description

Implement the API endpoints and database table for the pre‑alert marketplace on `sivel.xyz`, with:

1. **Agent sync endpoint** – receives pre‑alerts from `sivel3agent` (#7) with **wallet signature** authentication (no API keys)
2. **Source transparency** – citizens can see source URLs *before* purchasing (informed purchase)
3. **Real on‑chain purchases** via `PreAlertMarket.sol` (#43)
4. **Documenter scoring** (2–5) – citizen reward equals the score (i.e., score 4 → $4 USDT)
5. **Simple rejection** – documenter can reject the alert (score 0), no payment

**Why source transparency?**
- Citizens need to verify the credibility of sources before buying (no refunds)
- If the source is unreliable (e.g., tabloid, anonymous), the citizen can skip
- This builds trust in the marketplace and reduces wasted purchases

## Database Table

```sql
CREATE TABLE pre_alert (
    id BIGSERIAL PRIMARY KEY,
    event_hash VARCHAR(66) UNIQUE NOT NULL,
    json_data JSONB NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'pending',
    publisher_wallet VARCHAR(42) NOT NULL,
    buyer_wallet VARCHAR(42),
    bought_at TIMESTAMP,
    conversion_deadline TIMESTAMP,
    converted_at TIMESTAMP,
    tx_hash VARCHAR(66),
    source_urls TEXT[],                          -- ✅ Array of URLs (visible to citizens)
    source_summary TEXT,                         -- ✅ Optional: short description of sources
    contract_pre_alert_id INTEGER,
    score INTEGER,
    scored_by VARCHAR(42),
    scored_at TIMESTAMP,
    rejection_reason TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_pre_alert_status ON pre_alert(status);
CREATE INDEX idx_pre_alert_event_hash ON pre_alert(event_hash);
```

**What citizens see before purchase:**
- `titulo`, `fecha`, `departamento`, `municipio` (from `json_data`)
- `source_urls` (full list of URLs)
- `source_summary` (brief description of sources, e.g., "El Tiempo, 2025-09-07")
- `status` (must be `pending`)

**What citizens see after purchase:**
- Full `json_data` (all fields)

## API Endpoints

### 1. Agent Sync Endpoint

#### `POST /api/pre-alerts/sync`

Receives a new pre‑alert from the AI agent (`sivel3agent#7`).

**Authentication:** Wallet signature (no API keys). The agent signs the `event_hash` with its private key. The server verifies the signature against `AGENT_WALLET_ADDRESS`.

**Headers:**
| Header | Value |
|--------|-------|
| `X-Agent-Signature` | `0x...` (65‑byte ECDSA signature of `event_hash`) |
| `X-Agent-Timestamp` | ISO 8601 timestamp (prevents replay within ±5 min window) |

**Request:**
```json
{
    "event_hash": "0x...",
    "json_data": { ... },
    "publisher_wallet": "0x...",
    "source_urls": ["https://...", "https://..."],
    "source_summary": "El Tiempo, 2025-09-07"
}
```

**Signature verification (server‑side):**
```typescript
import { verifyMessage } from 'viem'

const message = `${body.event_hash}:${timestamp}`
const recovered = await verifyMessage({
  message,
  signature: headers['x-agent-signature'],
})
if (recovered.toLowerCase() !== AGENT_WALLET_ADDRESS.toLowerCase()) {
  return 401 Unauthorized
}
// Also verify timestamp is within ±5 minutes
if (Math.abs(Date.now() - new Date(timestamp).getTime()) > 5 * 60 * 1000) {
  return 401 Unauthorized
}
```

**Agent‑side (sivel3agent #7):**
```bash
# Sign the event_hash + timestamp
./bin/m wallet:sign --name sivel3agent --message "${eventHash}:$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

**Why wallet signature instead of API key:**
- No secrets to manage, rotate, or leak
- Cryptographic proof of agent identity
- Aligned with Web3 architecture
- Same wallet already used for on‑chain publishing

**Validation:**
- `event_hash` must be unique → `409 Conflict` if exists
- `json_data` must validate against `relato.schema.json` → `400 Bad Request` if invalid
- `source_urls` must be non‑empty → `400 Bad Request` if empty

**Response (201 Created):**
```json
{
    "success": true,
    "pre_alert_id": 123,
    "status": "pending",
    "event_hash": "0x..."
}
```

### 2. Citizen Endpoints

#### `GET /api/pre-alerts`

Lists pending pre‑alerts with **source URLs visible** (no purchase required).

**Query Parameters:**
| Param | Type | Description |
|-------|------|-------------|
| `page` | integer | Page number (default: 1) |
| `limit` | integer | Items per page (default: 20, max: 100) |
| `departamento` | string | Filter by department (optional) |
| `municipio` | string | Filter by municipality (optional) |

**Response (200 OK):**
```json
{
    "pre_alerts": [
        {
            "id": 1,
            "titulo": "Asesinato de líder social en Puerto Guzmán",
            "fecha": "2025-09-07",
            "departamento": "Putumayo",
            "municipio": "Puerto Guzmán",
            "status": "pending",
            "source_urls": ["https://www.periodicoputumayo.com/...", "https://www.eltiempo.com/..."],
            "source_summary": "Periodico Putumayo, El Tiempo"
        }
    ],
    "total": 42,
    "page": 1,
    "limit": 20
}
```

#### `GET /api/pre-alerts/:id`

Returns full pre‑alert JSON **only if** the requesting wallet has purchased it (or is a documenter/admin).

**Pre‑purchase (citizen not buyer):**
```json
{
    "id": 1,
    "status": "pending",
    "titulo": "Asesinato de líder social en Puerto Guzmán",
    "fecha": "2025-09-07",
    "departamento": "Putumayo",
    "municipio": "Puerto Guzmán",
    "source_urls": ["https://..."],
    "source_summary": "El Tiempo",
    "can_purchase": true
}
```

**Post‑purchase (citizen is buyer):**
```json
{
    "id": 1,
    "json_data": { ... },
    "status": "reserved",
    "bought_at": "2025-09-07T10:00:00Z",
    "conversion_deadline": "2025-09-14T10:00:00Z"
}
```

#### `POST /api/pre-alerts/:id/buy`

Purchases a pre‑alert (on‑chain via `PreAlertMarket.sol`).

**Request:**
```json
{
    "buyer_wallet": "0x...",
    "payment_token": "0xUSDT_ADDRESS",
    "priceUSD": 1
}
```

**Flow:**
1. Verify pre‑alert is `pending`
2. **No refund policy** – purchase is final
3. Call `buyPreAlert` on `PreAlertMarket.sol`
4. Update status to `reserved`, set `buyer_wallet`, `bought_at`, `conversion_deadline`

**Response:**
```json
{
    "success": true,
    "tx_hash": "0x...",
    "status": "reserved",
    "expires_at": "2025-09-14T10:00:00Z"
}
```

#### `POST /api/pre-alerts/convert`

Converts a reserved pre‑alert into a citizen alert (off‑chain).

**Request:**
```json
{
    "pre_alert_id": 1,
    "enriched_json": { ... },
    "additional_data": "optional notes"
}
```

**Flow:**
1. Verify pre‑alert is `reserved` and `buyer_wallet` matches
2. Verify not expired (`conversion_deadline > NOW()`)
3. Validate `enriched_json` against `relato.schema.json`
4. Store enriched JSON in `alert` table (or as versioned data)
5. Update status to `converted`, set `converted_at`

**Response:**
```json
{
    "success": true,
    "alert_id": 123,
    "status": "converted"
}
```

### 3. Documenter Endpoints

#### `GET /api/pre-alerts/queue`

Returns all `converted` pre‑alerts awaiting scoring.

**Authentication:** `DOCUMENTER_ROLE` (SBT)

**Response:**
```json
{
    "pending": [
        {
            "id": 1,
            "titulo": "...",
            "buyer_wallet": "0x...",
            "converted_at": "...",
            "json_data": { ... },
            "source_urls": [...],
            "original": { ... }  // original pre‑alert JSON for comparison
        }
    ],
    "total": 5
}
```

#### `POST /api/pre-alerts/:id/score`

Assigns a quality score (2–5) to a converted pre‑alert.

**Authentication:** `DOCUMENTER_ROLE` (SBT)

**Request:**
```json
{
    "score": 4,
    "feedback": "Good documentation, clear sources. Missing some victim names."
}
```

**Scoring rules:**
| Score | Meaning | Payment |
|-------|---------|---------|
| 0 | Rejected | $0 |
| 2 | Minimum quality | $2 |
| 3 | Acceptable | $3 |
| 4 | Good | $4 |
| 5 | Excellent | $5 |

**Flow:**
1. Verify pre‑alert status is `converted`
2. If score is 0: reject with `rejection_reason`
3. If score is 2–5: store score, pay citizen `score` USDT
4. Update status to `scored` (or `rejected`)

**Response:**
```json
{
    "success": true,
    "pre_alert_id": 1,
    "status": "scored",
    "score": 4,
    "citizen_reward": "4 USDT"
}
```
