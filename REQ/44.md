## Description

Implement the API endpoints and database table for the pre‑alert marketplace on `sivel.xyz`, with:

1. **Real on‑chain purchases** via `PreAlertMarket.sol` (#43)
2. **Documenter scoring** (2–5) – citizen reward equals the score (i.e., score 4 → $4 USDT)
3. **Simple rejection** – documenter can reject the alert (score 0), no payment

**Why scoring instead of approve/reject?**
- Aligns with the Noche y Niebla quality scale (1–5)
- Citizen reward is directly proportional to quality
- Documenter has granular control: 2 (minimum quality) to 5 (excellent)
- No payment for scores below 2 (rejection)

## Database Table

```sql
CREATE TABLE pre_alert (
    id BIGSERIAL PRIMARY KEY,
    event_hash VARCHAR(66) UNIQUE NOT NULL,
    json_data JSONB NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'pending',
    publisher_wallet VARCHAR(42) NOT NULL,
    buyer_wallet VARCHAR(42),
    bought_at TIMESTAMP,
    conversion_deadline TIMESTAMP,
    converted_at TIMESTAMP,
    tx_hash VARCHAR(66),
    source_urls TEXT[],
    contract_pre_alert_id INTEGER,
    -- MVP2: Scoring
    score INTEGER,                      -- 2-5 (or 0 if rejected)
    scored_by VARCHAR(42),
    scored_at TIMESTAMP,
    rejection_reason TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_pre_alert_status ON pre_alert(status);
CREATE INDEX idx_pre_alert_event_hash ON pre_alert(event_hash);
```

## API Endpoints

### Citizen endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/pre-alerts` | GET | List pending pre‑alerts |
| `/api/pre-alerts/:id` | GET | Full pre‑alert JSON |
| `/api/pre-alerts/:id/buy` | POST | Buy pre‑alert (on‑chain) |
| `/api/pre-alerts/convert` | POST | Convert to alert (off‑chain) |

### Documenter endpoints

#### `GET /api/pre-alerts/queue`

Returns all `converted` pre‑alerts awaiting scoring.

**Authentication:** `DOCUMENTER_ROLE` (SBT) – verified via `verifyDocumenter` middleware

**Response:**
```json
{
    "pending": [
        {
            "id": 1,
            "titulo": "...",
            "buyer_wallet": "0x...",
            "converted_at": "...",
            "json_data": { ... }
        }
    ],
    "total": 5
}
```

#### `POST /api/pre-alerts/:id/score`

Assigns a quality score (2–5) to a converted pre‑alert.

**Authentication:** `DOCUMENTER_ROLE` (SBT)

**Request:**
```json
{
    "score": 4,
    "feedback": "Good documentation, clear sources. Missing some victim names."
}
```

**Scoring rules:**
| Score | Meaning | Payment to citizen | Notes |
|-------|---------|-------------------|-------|
| 0 | Rejected | $0 | Citizen receives nothing. Requires `reason` field. |
| 2 | Minimum quality | $2 | Basic information, some sources. Needs improvement. |
| 3 | Acceptable | $3 | Complete information, verifiable sources. |
| 4 | Good | $4 | Well‑structured, multiple sources, clear act classification. |
| 5 | Excellent | $5 | Fully documented, follows Noche y Niebla methodology perfectly. |

**Flow:**
1. Verify pre‑alert status is `converted`
2. If score is 0:
   - Update status to `rejected`
   - Store `score=0`, `rejection_reason`
3. If score is 2–5:
   - Update status to `scored`
   - Store `score`, `scored_by`, `scored_at`
   - **Pay citizen `score` USDT** (e.g., score 4 → $4)
4. If score is 1: reject with reason (score 1 is not used)

**Response:**
```json
{
    "success": true,
    "pre_alert_id": 1,
    "status": "scored",
    "score": 4,
    "citizen_reward": "4 USDT"
}
```

## Score Quality Guidelines (for Documenters)

| Score | Criteria |
|-------|----------|
| **5** | All fields complete. `hechos` follows Noche y Niebla style (QUIÉN + QUÉ + A QUIÉN). Multiple sources. Clear act classification. Context accurately identified. |
| **4** | All required fields present. Minor issues in narrative or sources. Classification correct. |
| **3** | Most fields present. Some missing information (e.g., no context, incomplete victims list). Classification acceptable. |
| **2** | Basic information present but incomplete. Sources are weak or missing. Classification may be ambiguous. |
| **0** | Information is unreliable, sources are not credible, or alert is fabricated. Reject. |
