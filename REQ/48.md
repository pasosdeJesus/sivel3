## Description

Implement the user interface for the pre‑alert marketplace on `sivel.xyz`,
enabling citizens to:

1. **View pre‑alerts** on the map (special 🤖 markers, visible only to verified
   learn.tg users)
2. **Buy pre‑alerts** for $1 USDT (wallet connection via MiniPay/MetaMask)
3. **Convert pre‑alerts** to citizen alerts (editable JSON form)
4. **Track purchases** in a dashboard
5. **Review and score** alerts (documenter panel)

**Critical UX requirement:** Every step must inform the user about:
- The non‑guaranteed nature of rewards
- Dependence on fund availability
- Documenter discretion

---

## Tasks

### 1. Map Layer

- [ ] Modify `MapComponent.tsx` to fetch pre‑alerts from `GET /api/pre-alerts`
- [ ] Display pre‑alerts as grey 🤖 markers (pending) and green 🤖 (reserved)
- [ ] Add learn.tg verification check before showing the layer
- [ ] Info window: title, date, location, sources, price, "Buy" button

- [ ] Create `PreAlertModal.tsx` component
- [ ] Wallet connection (MiniPay detection)
- [ ] **Display pre‑purchase warning** (funds not guaranteed, no refunds)
- [ ] Call `POST /api/pre-alerts/:id/buy` with payment token
- [ ] Show confirmation: "Expires in 7 days"

### 3. Conversion Flow

- [ ] Create `ConvertForm.tsx` component
- [ ] Display pre‑alert JSON in editable form
- [ ] Validate against `relato.schema.json` (using `ajv` on frontend)
- [ ] **Display conversion warning** (reward depends on funds + quality)
- [ ] Call `POST /api/pre-alerts/convert`
- [ ] Show confirmation: "Awaiting documenter review"

### 4. Citizen Dashboard

- [ ] Create `/dashboard` page
- [ ] List purchased pre‑alerts (reserved, converted, paid, pending_reward)
- [ ] Show status and deadlines
- [ ] **Display fund status** ("Funds available: $X", "Pending funds")
- [ ] "Convert" button for eligible alerts

### 5. Documenter Panel

- [ ] Create `/documenter` page (requires `DOCUMENTER_ROLE`)
- [ ] List converted pre‑alerts (from `GET /api/pre-alerts/queue`)
- [ ] Score modal (0-5)
