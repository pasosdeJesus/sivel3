# Internationalization (i18n) Guide - SIVeL 3

This document explains how internationalization is implemented in the Next.js application and provides guidelines for developers to maintain and extend it.

---

## 1. Routing and Language Detection

We use a **sub-path routing** strategy with a dynamic segment `[locale]`.

*   **Middleware:** The `middleware.ts` file detects the user's preferred language using the `accept-language` header and redirects to the appropriate sub-path (e.g., `/` -> `/es/`).
*   **Static Assets:** API routes and files in the `public/` directory are excluded from translation redirects.

---

## 2. Translation Pattern: Zero-Dependency TypeScript

The project follows a **zero-dependency, local TypeScript pattern** for internationalization. 

**Why?** Traditional i18n libraries (like `next-i18next` or `next-intl`) have shown compatibility or performance issues when running on **OpenBSD/adJ**. By using pure TypeScript objects, we ensure maximum performance, no external dependencies, and full type safety.

### Pattern: Local TypeScript Objects
Each component or feature file contains its own translation object.

*   **Location:** Inside the same `.tsx` or `.ts` file of the component/feature.
*   **Pattern:**
    ```typescript
    const localTranslations = {
      en: { title: 'Hello', description: 'World' },
      es: { title: 'Hola', description: 'Mundo' }
    };
    ```

#### A. Usage in Client Components (with Hook)
```tsx
'use client';
import { useTranslation } from '@/hooks/useTranslation';

export function MyComponent() {
  const { t, locale } = useTranslation(localTranslations);
  return <h1>{t('title')}</h1>;
}
```

#### B. Usage in Server Components (Universal)
Server components cannot use hooks. Instead, use the pure function `createTranslator` and pass the `locale` from the page params.

```tsx
import { createTranslator } from '@/hooks/useTranslation';

export default async function ServerPage({ params }: { params: { locale: string } }) {
  const { locale } = await params;
  const t = createTranslator(locale as 'en' | 'es', localTranslations);
  
  return <h1>{t('title')}</h1>;
}
```

---

## 3. Global Translations (Common Terms)

Terms that are used across the entire application (e.g., "Cancel", "Save", "Error") are stored in `lib/i18n/common.ts`. Both the hook and the universal translator will automatically fallback to these common terms if a key is not found in the local translation object.

## 3. Step-by-Step: Adding a New Language String

1.  **Identify the Scope:** Open or create the `locales/` directory and translation file in the directory of the page or feature you are working on.
2.  **Add the Key:** Add the string in both `en` and `es` sections to maintain parity.
3.  **Use in Component:**
    *   Extract the `locale` from params or the URL.
    *   Access the string via `translations[locale]`.

---

## 4. Best Practices

*   **Parity:** Always add keys to all supported languages simultaneously.
*   **Placeholders:** Use double curly braces `{{variable}}` for dynamic content within strings.
*   **Types:** Use `keyof typeof translations.en` to ensure type safety when passing keys as props.
